# Render로 팀 공유용 시연 서버 올리기

시연 사이트를 만든다. 무료 요금제 기준이다.
지금은 `SITE_PUBLIC=1`(render.yaml)이라 **접속 코드 없이 링크만으로** 누구나 들어온다(2026-11-03부터). 담당자 화면은 여전히 로그인해야 한다.
다시 팀원만 들어오게 하려면 `SITE_PUBLIC`을 `0`으로 바꾸고 `SITE_ACCESS_CODE`를 정한다(아래는 코드를 쓰는 경우의 설명).
모든 데이터는 가상이고, 실제 출동·문자 발송은 일어나지 않는다. 학교 프로젝트라면 올리기 전에 지도 선생님께 알린다.

## 1. 미리 정할 값 (메모장에 적어 두기)

| 이름 | 무엇 | 예 |
|---|---|---|
| `SITE_ACCESS_CODE` | 팀원에게 링크와 함께 줄 접속 코드(6자 이상) | `geoje-team-1029` 같은 문구 |
| `DEMO_ADMIN_PASSWORD` | 담당자 화면 `시연담당` 계정 비밀번호(8자 이상). 접속 코드와 다르게 | |
| `UPSTAGE_API_KEY` | Solar 키(이 PC에 저장한 것과 같은 값) | |
| `KMA_API_KEY` | 공공데이터포털 인증키(Decoding). 없으면 비워도 됨(날씨만 '확인 불가') | |
| `TURSO_DATABASE_URL` | Turso DB 주소(`libsql://…turso.io`). 아래 7번에서 만든다. 비우면 재시작할 때 데이터가 지워짐 | |
| `TURSO_AUTH_TOKEN` | Turso DB 토큰 | |

키 값은 Render 화면에만 입력한다. 저장소·채팅·문서에 적지 않는다.

## 2. Render에서 할 일

1. https://render.com 에 들어가 **GitHub로 로그인**한다(`demoday03` 계정). 계정 만들기와 로그인은 직접 한다.
2. 위쪽 **New +** → **Blueprint**를 고른다.
3. 저장소 `demoday03/disaster-agents`를 고른다. 처음이면 GitHub에서 Render에 저장소 접근을 허락하는 화면이 나온다.
4. 브랜치가 `claude/solar-connection-verify-byjenq`인지 확인한다(아직 main에 합치지 않았으므로).
5. Render가 `render.yaml`을 읽어 서비스 `disaster-agents`를 보여 준다. 비밀 값 4개 입력 칸에 1번에서 정한 값을 넣는다.
6. **Apply**(또는 Deploy)를 누른다. 처음 배포는 2~5분 걸린다.
7. 서비스 화면 위쪽의 주소(예: `https://disaster-agents-xxxx.onrender.com`)가 팀원에게 줄 **링크**다.

## 3. 확인

- 링크를 열면 **접속 코드** 화면이 나온다 → 코드 입력 → 시민 화면.
- `링크/admin` → 접속 코드(이미 넣었으면 생략) → 담당자 로그인(`시연담당` / `DEMO_ADMIN_PASSWORD`).
- `링크/volunteer` → 봉사자 화면.
- 문제가 있으면 Render 서비스 화면의 **Logs**를 본다. 서버가 안 뜨는 흔한 이유:
  - `SITE_ACCESS_CODE가 필요` → 접속 코드가 비었거나 6자 미만
  - `DEMO_ADMIN_PASSWORD(8자 이상)` → 비밀번호가 짧음
  - `LLM_MODE=solar requires UPSTAGE_API_KEY` → Solar 키를 안 넣음

## 4. 팀원에게 보낼 내용

```
재난 안전 AI 시연 사이트: https://(Render 주소)
접속 코드: (SITE_ACCESS_CODE)
담당자 화면은 링크 뒤에 /admin, 봉사자 화면은 /volunteer
처음 들어가면 30초~1분 걸릴 수 있어요(무료 서버가 깨어나는 중).
모든 데이터는 가상이고 실제 개인정보는 넣지 마세요.
```
담당자 비밀번호는 담당자 역할을 할 팀원에게만 따로 준다.

## 5. 알아 둘 점(무료 요금제)

- 15분쯤 아무도 안 들어오면 서버가 잠든다. 다음 첫 접속이 30초~1분 걸린다.
- Turso를 연결하지 않았다면, 서버가 다시 시작되거나 새로 배포되면 **데이터가 처음 상태로 돌아간다**(신고 6건이 자동으로 다시 들어감). 시연 연습에는 오히려 편하다.
- Solar 호출은 서버가 켜져 있는 동안 300회(`SOLAR_MAX_CALLS`)까지만 하고, 넘으면 규칙으로만 동작한다. 공개 화면 요청은 접속 IP당 분당 30건으로 제한한다.
- 이 브랜치에 push하면 자동으로 다시 배포된다.
- 그만 공개하려면 Render 서비스 화면에서 **Suspend**(일시 중지) 또는 **Delete**. 접속 코드를 바꾸면(Environment에서 수정 → 저장) 예전 코드로 들어온 사람은 다시 코드를 넣어야 한다.
- 센서 게이트웨이(마이크로비트)는 이 배포에 연결하지 않는다(`SENSOR_GATEWAY_TOKEN` 없음 → 센서 입력 경로 닫힘). 센서 시연은 PC 로컬 서버로 한다.

## 6. 코드 쪽 동작(참고)

- `RENDER=true`(Render가 자동 설정) 또는 `WEBAPP_CLOUD=1`이면 클라우드 모드: `0.0.0.0:$PORT`로 열고, Render 주소를 허용 Host에 넣고, 쿠키에 Secure를 붙이고, 접속 IP는 `X-Forwarded-For`로 본다.
- 클라우드 모드는 접속 코드(6자 이상)와 담당자 계정이 없으면 시작하지 않는다(`check_bind_policy`). 단 `SITE_PUBLIC=1`을 명시하면 접속 코드 없이 시작하고, 설정된 접속 코드도 무시한다.
- 공개(`SITE_PUBLIC=1`)일 때 보호 장치: 담당자 기능은 로그인·CSRF 필요, 신고는 IP당 분당 제한, Solar 호출은 300회 상한.
- 접속 코드는 `/access`에서 받고, 맞으면 30일짜리 HttpOnly 쿠키를 준다. `/api/health`(Render 상태 확인)와 게이트웨이 경로만 코드 없이 열린다.
- `DEMO_SEED_ON_START=1`이고 계정이 없으면 시작할 때 `scripts/demo_setup.py`와 같은 시연 데이터를 넣는다.

## 7. 데이터가 남게 하기: Turso 연결

무료 서버는 다시 시작하면 디스크가 비어서, 가입한 봉사자 계정·주민이 적은 우리 집·신고가 사라진다.
Turso(클라우드 SQLite, 무료 요금제 있음)를 연결하면 이 데이터가 Turso에 저장되어 남는다.

1. https://turso.tech 에 가입하고 로그인한다(GitHub 로그인 가능). 계정 만들기는 직접 한다.
2. **Databases → Create Database**. 이름은 `disaster-agents`, 지역은 Render(싱가포르)와 가까운 곳(예: Tokyo `aws-ap-northeast-1`)을 고른다.
3. 만든 DB 화면에서 **URL**(`libsql://disaster-agents-<계정>.turso.io` 모양)을 복사한다.
4. 같은 화면에서 **Create Token**(읽기·쓰기, 만료 없음 또는 충분히 길게)으로 토큰을 만들어 복사한다. 토큰은 비밀번호와 같다.
5. Render 서비스 화면 → **Environment**에서 `TURSO_DATABASE_URL`과 `TURSO_AUTH_TOKEN`에 붙여 넣고 저장한다. 저장하면 다시 배포된다.
6. 확인: `링크/api/health`를 열어 `"database": "Turso(libSQL)"`이 보이면 연결된 것이다. 봉사자로 가입한 뒤 Render에서 **Manual Deploy → Restart**를 해도 로그인이 되면 성공.

알아 둘 점
- 처음 연결하면 Turso DB가 비어 있으므로 서버가 시연 계정과 신고 6건을 한 번 넣는다(`DEMO_SEED_ON_START`). 그 뒤로는 다시 넣지 않는다.
- 서버 안에는 빠른 읽기용 복제본(`data/demo-turso-replica.db`)만 두고, 쓰기는 Turso에 바로 저장한다. 다시 시작하면 복제본을 Turso에서 새로 받는다.
- 비밀번호는 원문이 아니라 해시만 저장된다(봉사자·담당자 모두). Turso 화면에서 표를 열어 봐도 비밀번호는 보이지 않는다.
- 처음 상태로 되돌리려면 Turso에서 DB를 지우고 새로 만든 뒤 URL·토큰을 다시 넣는다.
- 토큰이 새어 나갔다면 Turso에서 토큰을 폐기(rotate)하고 새 토큰으로 바꾼다.
- 내부망(학교 PC) 배포는 Turso 없이 그 PC의 SQLite 파일을 쓴다(`docs/내부망_배포_점검표.md`).

## 8. 주민 알림: 텔레그램 봇

주민이 앱을 열지 않아도 위기 단계·공지·안부 확인이 텔레그램으로 온다. 보내는 내용은 담당자가 직접 쓰거나 승인한 것뿐이다.

1. 텔레그램에서 **@BotFather**에게 `/newbot` → 봇 이름과 아이디(끝이 `bot`)를 정하면 **토큰**을 준다. 토큰은 비밀번호와 같다.
2. Render → **Environment**에 `TELEGRAM_BOT_TOKEN`으로 넣고 저장(다시 배포됨).
   - 담당자 단체방·주민 공지 채널은 환경 변수 없이 **관리자 화면 → 📨 텔레그램**에서 연결한다(아래 '담당자 방·공지 채널').
3. 확인: `링크/api/health`의 `"telegram"`에 `"enabled": true, "mode": "webhook"`, `"bot": "봇아이디"`가 보이면 연결된 것이다.
   `"error"`가 보이면 토큰을 다시 확인한다.
4. 주민 화면 **알림**·**우리 집** 메뉴에 "📲 텔레그램으로 알림 받기"가 나타난다. 누르고 텔레그램에서 **시작**을 누르면 구독된다.
   우리 집을 저장한 뒤 누르면 그 집과 연결되어, 담당자가 안부 확인을 시작하면 텔레그램에 **✅ 안전합니다** 버튼이 온다.

봇이 보내는 것
- 주민 대상 공지(모두·주민). 긴급 공지는 🚨로 표시. 구역을 정한 공지는 그 구역 집(과 집을 연결하지 않은 구독자)에만.
  공지 채널을 연결하면 모두에게 보내는 공지는 채널에만 한 번 올린다(아래).
- 담당자가 확정한 위기 단계(주의·경계·위험)와 단계별 행동 한 줄.
- 우리 집 안부 확인 요청과 '안전합니다' 버튼(누르면 담당자 화면에 '안전'으로 기록).
- 봇에 `/상황`을 보내면 지금 위기 단계·공지·자리가 남은 대피소·통제 중인 길을 답한다. `/stop`이면 그만 보낸다.

봇으로 신고하기(웹 신고와 같은 접수 에이전트·승인 흐름)
- 아래쪽 메뉴의 **🆘 신고하기**(또는 `/report`) → ① 무슨 일인지 버튼으로 여러 개 고르기 → **다음** →
  ② 위치를 입력창에 적거나 **📍 지금 위치 보내기**(휴대폰) → ③ 더 알려 줄 것을 입력창에 적기(**건너뛰기** 가능) → **✅ 신고 보내기**.
- 접수되면 접수번호·종류·긴급도와 **🔄 진행 상황 / ❌ 신고 취소** 버튼이 온다(취소는 한 번 더 묻는다).
- 위치처럼 꼭 필요한 정보가 빠지면 입력창을 열어 바로 묻는다. 적어 보내거나 위치를 보내면 신고에 보완된다.
- 담당자가 출동을 승인하거나 안내문을 승인하면 그 대화방으로 "🔔 신고 소식"이 온다. **📋 내 신고**(`/my`)로 최근 5건을 본다.
- 버튼 없이 글만 보내도 "이 내용으로 바로 신고할까요?"라고 묻는다(급할 때 한 번에).
- 담당자 화면의 신고 카드에 **📨 텔레그램 신고 · 신고자 T-XXXX**로 표시된다. 신고자 번호는 이름 대신 대화방마다 붙는 번호라
  같은 사람이 보낸 신고끼리 묶어 볼 수 있다(텔레그램 이름·아이디는 저장하지 않는다). 속도 제한은 대화방마다 따로 센다.
- **🏠 우리 집 연결**(`/code 우리집번호`)을 해 두면 신고에 그 가구가 붙어 **🏠 가구 … (로그인 신고)**로 보이고,
  위치를 물을 때 **🏠 우리 집** 버튼이 나온다. 안부 확인도 텔레그램 버튼으로 답할 수 있다. `/unlink`로 끊는다.
- 담당자는 텔레그램 신고 카드의 **💬 신고자에게 묻기**로 되물을 수 있다. 질문은 그 대화방으로 가고(입력창이 열림),
  신고자가 답하면 신고 카드에 붙고 담당자 화면에 알림이 뜬다. 답으로 분류가 바뀌지는 않는다(필요하면 '분류 수정').
- 쓰다 만 신고는 서버 메모리에만 30분 둔다(재시작하면 처음부터). 보낸 신고와 알림 기록은 DB에 남는다.
- 접수되면 **📞 내 연락처 보내기**(선택)를 묻는다. 누르면 텔레그램이 **본인 번호**를 보낸다(주소록에서 고른 남의 연락처는 받지 않는다).
  번호는 담당자 화면에만 **📞 신고자가 연락처를 보냄 · 번호 보기**로 보이고, 누가 열어 봤는지 기록이 남는다. 접수번호 조회에는 없다.
  신고를 취소·오접수 처리하면 바로, 아니면 48시간(`CONTACT_TTL_H`) 뒤 지운다. 신고자가 **🗑 연락처 지우기**로 직접 지울 수도 있다.

담당자 방·공지 채널(관리자 화면 → 📨 텔레그램, 1회용 코드 10분)
- **👮 담당자 단체방**: [연결 코드 만들기] → **📲 텔레그램에서 단체방을 골라 봇 추가하기**를 누르고 방을 고르면 끝.
  (또는 봇을 방에 초대한 뒤 화면에 나온 `/staff@봇아이디 코드`를 보낸다.) 여러 방(최대 5개)을 연결할 수 있다.
  - 보내는 것: **매우 급함(긴급도 1)** 신고는 바로, 긴급도 1~2를 **5분** 동안 아무도 확인하지 않으면 한 번 더,
    나머지는 **30분**마다 숫자 요약만. 한 번에 3건 넘게 들어오면 한 메시지로 묶는다(신고가 수천 건이어도 방이 넘치지 않게).
  - 알림의 **👀 확인했어요**를 누르면 신고에 '담당자 확인'이 남고, 신고자에게 "👤 담당자가 신고 내용을 확인했어요"가 간다.
    관리자 화면에서 확인·분류 수정·승인해도 같고, 다른 방에 간 같은 알림도 '✅ 확인'으로 바뀐다.
  - 방에서 `/status`는 지금 현황, `/unstaff`는 연결 끊기. 알림에는 연락처·우리 집 번호를 넣지 않는다. 방에는 담당자만 초대한다.
  - 간격 바꾸기(선택): `TELEGRAM_STAFF_REMIND_S`(기본 300초), `TELEGRAM_STAFF_DIGEST_S`(1800초, 0이면 요약 안 함), `TELEGRAM_STAFF_BATCH`(3건).
- **📢 주민 공지 채널**: 텔레그램에서 채널을 만들고 봇을 **관리자**로 넣은 뒤(메시지 보내기·삭제 권한), [연결 코드 만들기]에 나온
  `/channel 코드`를 채널에 글로 올린다. 봇이 그 글을 지우고 연결한다(비공개 채널이면 초대 링크를 만들어 둔다). 채널은 하나만.
  - 연결하면 **모두에게 보내는 공지·위기 단계는 채널에 한 번만** 올린다. 구독자가 몇만 명이어도 채널 글 하나로 끝난다.
    봇의 1:1 대화는 신고 답장·담당자 질문·우리 집 안부 확인처럼 그 사람에게만 필요한 것에 쓴다. 구역 공지는 그 구역에 연결된 집에도 1:1로.
  - 연결하는 순간 지금 구독자에게 "이제 공지는 채널에서" 안내와 **📢 공지 채널 들어가기** 버튼을 한 번 보낸다. 주민 화면에도 채널 버튼이 생긴다.
- 채널을 연결하지 않으면 예전처럼 구독자 모두에게 1:1로 보낸다. 이때도 **신고 답장·버튼 응답이 먼저** 나가고 공지는 그 사이사이에 보낸다
  (공지 수천 건 때문에 급한 신고 답장이 밀리지 않게). 텔레그램이 "너무 많이 보냄"(429)이라고 하면 기다렸다가 다시 보낸다.

알아 둘 점
- Render에서는 웹훅으로 받는다(`RENDER_EXTERNAL_URL` 자동 사용). 텔레그램이 보내는 요청이 잠든 무료 서버를 깨우지만, 깨어나는 동안(30초~1분) 답이 늦을 수 있다.
- 같은 토큰을 다른 곳(이 PC 등)에서 동시에 켜면 마지막에 켠 쪽이 메시지를 가져간다. 한 곳에서만 켠다. 내부망 PC는 공개 주소가 없어 폴링으로 받는다.
- 구독자 목록은 DB(Turso)에 저장되어 재시작해도 남는다.
