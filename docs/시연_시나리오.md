# 시연 시나리오 (약 15분)

가상 마을(구역 Z1~Z10)에 집중호우가 내린 상황을 처음부터 끝까지 보여 준다. 모든 데이터는 가상이고, mock 모드(AI API 없음)에서도 끝까지 진행된다. 2026-10-28 기준 `scripts/rehearse_demo.py`로 아래 장면 전체를 mock·solar 두 모드에서 자동 리허설해 모두 통과했다(14/14, solar 37초).

**보여 줄 핵심 세 가지**
1. AI는 정리·추천만 하고, 단계 확정·투입·출고·안내문 표시는 **사람이 승인**해야 반영된다.
2. AI가 실패하거나 없어도 **규칙으로 끝까지** 동작하고, 화면에 'AI 미사용'이라고 표시된다.
3. 센서 → 신고 → 배치 → 안내 → 물품·봉사 → 복구까지 **에이전트 8개가 하나의 흐름**으로 이어진다. 물품 요청 신고는 접수에서 출고 계획까지 자동으로 이어지고, 사람은 마지막에 한 번 승인한다.
4. 잘못된 신고·빠진 정보·에이전트 오류가 생겨도 **멈추지 않고 정리**된다.

## 0. 준비 (시연 10분 전)

먼저 전체 흐름이 지금 PC에서 동작하는지 자동으로 확인한다(임시 DB를 따로 쓰므로 시연 DB에 영향 없음, 약 30초).

```powershell
python scripts/rehearse_demo.py          # UPSTAGE_API_KEY가 있으면 Solar로, 없으면 규칙으로
```

`13/13 통과`가 나오면 시연 DB를 만든다. 실패한 장면이 있으면 그 장면은 시연에서 빼거나 아래 '시연 중 문제가 생기면'을 본다.

```powershell
python scripts/demo_setup.py --reset
```

출력에 담당자 비밀번호, 서버 실행 명령, 게이트웨이 실행 명령이 나온다. 비밀번호는 메모해 둔다.

- **PowerShell 창 1**: 출력된 `[창 1: 서버]` 명령 세 줄을 그대로 붙여 넣는다.
- **PowerShell 창 2**: 출력된 `[창 2]`의 `$env:SENSOR_GATEWAY_TOKEN=...` 한 줄만 미리 넣어 둔다(게이트웨이는 장면 3에서 켬).
- **브라우저 탭 두 개**: `http://127.0.0.1:8765/report`(시민 화면), `http://127.0.0.1:8765/admin`(담당자 화면, 로그인해 둠)
- 실제 마이크로비트를 쓰면 수신기를 USB에 꽂고 `python gateway/microbit_gateway.py --list-ports`로 포트를 확인해 둔다. 수위 센서용 물컵을 준비한다.

미리 들어 있는 신고 6건: 인명구조(Z3, 긴급도 1) · 침수(Z1) · 토사(Z5) · 정전(Z2) · 물품 요청(Z6) · 맨홀(Z4)

서버를 켜면 이 6건도 에이전트에 자동으로 넘겨진다(solar 모드는 30초 정도 걸림). 상황판에서 각 신고 아래 '④ 배치 추천 · ③ 안내문 검증 통과 → 승인 대기' 또는 '⑧ 물품 요청 자동 생성'이 보이고, 신고마다 **대응안 한 번에 승인** 버튼이 생긴다. 서버 창에 "저장된 신고 6건을 에이전트에 연결했습니다"가 나오면 끝난 것이다.

다시 시연할 때는 서버를 끄고 `python scripts/demo_setup.py --reset`부터 다시 한다(비밀번호가 바뀐다).

## 장면 3. 센서가 침수를 감지한다 (① 감시) — 3분

창 2에서:
```powershell
python gateway/microbit_gateway.py --simulate flood --ticks 8      # 실제 기기: --port COM3, 수위 센서 두 개를 물컵에 담근다
```

- 처음 1~2초는 '정상/일시 튐'이다. **연속 3회** 넘어야 **확정후보 · 제안 단계 경계 · 침수**가 되고, 승인 대기열에 1건이 올라간다. 값이 계속 높아도 승인 요청은 더 늘지 않는다.
- 말할 것: "센서 하나만 튀면 오탐일 수 있어서, 높이가 다른 수위 센서 두 개가 함께 3번 연속 넘어야 후보가 됩니다. 그래도 단계는 바뀌지 않고 담당자에게 승인을 요청합니다."
- (선택) `--simulate single`로 다시 보내면 '단독 반응 → 보류'가 된다.

**승인 대기열** 탭 → '위험 단계 확정' 항목 → 사유 `수위 센서 두 개가 함께 넘음, 현장 확인` → **승인**
→ **상황판**: 확정된 위험 단계 **경계 · 담당자 확정 · 시연담당 · 침수**

## 장면 4. 구조 인력을 배치한다 (④ 배치) — 3분

장면 1에서 보낸 Z7 인명구조 신고는 긴급도 1이라, 접수되자마자 **공공 인력 배치 추천이 승인 대기열에 자동으로 올라와 있다**(카드에 '긴급 신고 자동 추천'). 상황판의 신고 아래에도 '④ 배치 추천 AP-… (승인 대기열)'이 보인다.

- 말할 것: "생명이 걸린 신고는 담당자가 배치 화면을 열기 전에 추천부터 준비해 둡니다. 그래도 투입은 담당자가 승인해야 합니다. 같은 구역의 같은 사건이 반복 신고되면 배치를 또 만들지 않고 기존 배치에 연결합니다(인명구조는 놓치지 않게 항상 따로)."
- 긴급도 3~4 신고는 아래처럼 담당자가 직접 추천을 요청한다.

**④ 배치** 탭 → 신고 `R-DEMO0001`(Z3 인명구조) → 배치 종류 **공공 인력** → 추천 (미리 넣은 신고도 서버를 켤 때 자동 추천이 이미 올라가 있으므로, 이 화면은 추천 근거·대안을 자세히 보여 줄 때 쓴다. 이미 대기 중이면 그 추천 번호를 알려 준다)

- 결과: 1순위 **구조대 A (점수 0.87)**, 대안 구조대 B (0.84, 0.03점 차이) … 항목별 점수(역량·거리·부하·긴급도)가 함께 보인다.
- 말할 것: "점수는 규칙으로 계산합니다. 같은 입력이면 항상 같은 순위가 나오고, 왜 1순위인지 항목별로 보여 줍니다."
- 승인 카드에서 대안 후보(구조대 B)를 고르고 사유를 적어 **선택 후보로 승인**을 해 보인다. 1순위와의 점수 차이가 기록된다. (추천 밖 자원은 **직접 지정으로 승인** — 제약 위반이면 예외 승인과 사유가 필요)
- **통제 구간 관리**: 하천변 산책로(Z1↔Z6)·지하차도(Z4↔Z9)가 통제 중. 'C3 산사면 우회로 → 통제 시작'을 눌러, 그 구간을 지나야 하는 배치는 다음 추천에서 빠진다는 점을 설명한다.

## 장면 4-1. 신고 하나를 AI들이 이어서 처리하고(①②③④⑤⑦), 사람은 한 번만 승인한다 — 2분 (핵심 장면)

시민 화면에서 입력: `Z1 반지하 집에 물이 차요 할머니 혼자 계세요` → **신고 접수하기**

- 몇 초 뒤 담당자 화면 **상황판**: 신고 아래에 처리 결과가 줄줄이 붙는다. 담당자는 아무 버튼도 누르지 않았다.
  - ② 접수: 침수·취약 가구(긴급도 2), 인원 1명으로 분류
  - ① 감시: 센서와 교차 확인. 장면 3에서 센서도 침수를 감지했으면 "센서도 침수 감지", 아니면 "센서 근거 없음 → 단계는 센서 확인 후 확정". **신고 하나만으로 위험 단계를 올리지 않는다**(오탐 방지). 센서의 단계 확정 요청이 대기 중이면 이 신고의 승인 묶음에 함께 들어간다.
  - ④ 배치: 배수·구조 인력 추천 + 대피소 배정 추천(인원이 있을 때)
  - ③ 안내 → ⑦ 검증: 반지하·경계 단계 안내문을 쓰고(solar-pro4), 다른 AI(solar-pro3)가 근거와 맞는지 확인
  - ③ 안부: 그 구역 가구 안부 확인 시작 요청(긴급도 2 이하일 때, 승인해야 가구에 나감)
  - ⑤ 복구·지원: 해당 가능성이 있는 지원 항목 후보(참고용, 승인 대상 아님)
- 신고 옆 **대응안 한 번에 승인 (4건: 배치 승인(공공 인력), 배치 승인(대피소), 안부 확인 시작, 안내문 승인)** → 사유 입력 → 승인 4건. 배치가 투입되고, 안부 확인이 시작되고, 시민 화면 첫 페이지에 안내문이 근거와 함께 나타난다.
- 말할 것: "AI들이 서로 넘겨 가며 대응안을 다 준비하고, 사람은 마지막에 한 번 보고 결정합니다. 승인 직전에도 같은 팀이 다른 현장에 이미 갔는지, 재고가 남았는지 다시 점검해서 문제가 있는 항목만 건너뜁니다. 검증이 불확실한 안내문은 일괄 승인에서 빼고 따로 확인하게 합니다."
- 물품 요청(장면 7)과 일손 요청(`Z3 집 안 진흙 퍼낼 일손이 필요해요` → ⑥ 봉사자 추천)도 같은 버튼 하나로 승인된다.

## 장면 5. 주민 안내문을 만든다 (③ 안내 · ⑦ 검증) — 2분

**② 신고·③ 안내** 탭 → 신고 `R-DEMO0001` → 단계 **경계** → **통제 중인 구간 불러오기** → 생성

- mock 모드 결과: **표준 원문**("하천변·산사태 위험 지역에서 벗어나 … 통제 구간(하천변 산책로, 지하차도)은 피해서 이동하세요"), 근거 문서 ID `G-002, RULE-CTRL`

- **① 센서·⑦ 검증** 탭 아래 **⑦ 안내문 검증**: `주택 침수 세대는 재난지원금 500만원을 받습니다` + 근거 R1 선택 → 검증 → 근거(350만원)에 없는 숫자 500이라 **notGrounded(차단)**.

## 장면 6. 무응답 가구를 찾는다 (③ 안부) — 1분

**③ 안부** 탭 → 구역 Z3 → 응답 대기 시간 `10`초 → **안부 확인 시작**

- 말할 것: "격상은 담당자 알림까지만입니다. 출동은 다시 사람이 결정합니다."

## 장면 7. 신고 하나로 물품이 나간다 (② 접수 → ⑧ 물품) — 2분

시민 화면에서 입력: `Z6 마을회관인데 생수 12병이랑 담요 5장 필요해요` → **신고 접수하기**

- 담당자 화면 **상황판**: 신고 아래에 **접수 · ⑧ 물품 요청 SR-… 자동 생성**이 보인다.
- **승인 대기열**: '물품 배치 승인(출고)' 2건(생수 12, 담요 5). 카드에 **"이 승인 한 번으로 검토와 출고가 함께 확정됩니다"**와 어느 창고에서 몇 개를 보낼지가 나온다. **⑧ 물품** 탭 재고는 아직 그대로다.

- (예전 방식) 물품 탭에서 가구·품목을 직접 등록하고 검토 승인 → 배치 승인을 따로 하는 흐름도 그대로 있다.

담당자 화면 **상황판** → 아무 신고(예: 방금 물품 신고)의 **오접수 처리** → 사유 `같은 번호 반복 장난 신고`

- 말할 것: "잘못된 신고 하나 때문에 묶였던 인력과 재고를 한 번에 풀고, 누가 왜 처리했는지 기록합니다. 이미 출고된 물품은 바꾸지 않고 담당자에게 알려 회수 여부를 판단하게 합니다."

## 장면 8. 봉사자를 투입한다 (⑥ 봉사) — 1분 (시간이 남으면)

## 예상 질문과 답

| 질문 | 답 |
|---|---|
| AI가 틀리면? | 형식이 맞지 않는 AI 출력은 버리고 규칙으로 대신한다. 인명구조 키워드가 있으면 AI가 다르게 분류해도 인명구조로 올린다. 모든 반영은 사람 승인 뒤다. |
| 인터넷이 끊기면? | AI 호출이 실패하면 규칙 폴백으로 계속 동작한다(오늘 시연이 그 상태). 서버와 DB는 이 PC 안에 있다. |
| 센서가 고장 나면? | 30초 넘게 값이 없으면 '노드 응답 끊김'으로 판정에서 빼고 보류한다(`--simulate dropout`). |
| 개인정보는? | 신고문·서류의 전화번호·주민번호·이메일은 저장 전에 가린다. 가구·봉사자는 코드로만 다룬다. 서류 원본은 저장하지 않는다. |
| 신고가 잘못됐으면? | 담당자가 '오접수 처리'를 하면 그 신고에 걸린 대기 승인은 반려, 투입된 배치는 해제, 출고 전 물품 예약은 취소되고 감사 기록이 남는다. |
| 필수 정보가 빠지면? | 위치나 품목을 못 찾으면 '보완 필요'로 두고 다음 단계로 넘기지 않는다. 신고자가 접수번호로 보완하면 다시 분류해 이어 간다. 인명구조는 위치가 없어도 긴급도 1이다. |
| 에이전트 하나가 고장 나면? | 그 에이전트만 '수동 처리 중'으로 표시하고 나머지는 계속 동작한다. 접수와 승인 대기열만 살아 있으면 담당자가 화면에서 직접 처리해 지원을 이어 갈 수 있다. 접수 분류기가 멈춰도 신고는 '미분류'로 저장된다. |
| 실제로 쓸 수 있나? | 아니다. 교육용 프로토타입이다. 임계값·안전 기준·안내 문구는 공식 자료로 확인해야 하고, 실제 출동·경보는 일어나지 않는다. |
| 아무나 센서 값을 보내면? | 서버는 게이트웨이 토큰이 맞아야 받는다. 다만 마이크로비트 무선 구간에는 인증이 없어, 자동 경보 대신 담당자 승인만 요청하도록 설계했다. |

## 시연 중 문제가 생기면

| 증상 | 조치 |
|---|---|
| 로그인이 안 됨 | 설정 출력의 비밀번호를 다시 확인. 5번 틀리면 10분 잠김 → `--reset`으로 새로 만든다. |
| 게이트웨이 'HTTP 401' | 창 1과 창 2의 `SENSOR_GATEWAY_TOKEN`이 다르다. 같은 값으로 맞춘다. |
| 게이트웨이 'HTTP 503' | 서버를 토큰 없이 켰다. 창 1에서 토큰을 넣고 서버를 다시 켠다. |
| 게이트웨이 '연결할 수 없습니다' | 서버가 꺼져 있거나 주소가 다르다(`--server http://127.0.0.1:8765`). |
| 센서 판정이 계속 '보류' | 노드 하나가 끊겼다. 수신 현황의 노드 표시를 본다. 실제 기기면 무선 그룹 번호(`GROUP`)를 확인한다. |
| 배치 추천이 '후보 없음' | 이미 투입 중인 자원이 많다. 배치 보드에서 해제하거나 `--reset`. |
| 에이전트 카드가 '수동 처리 중' | 그 기능에서 오류가 났다. 서버 창의 오류 로그를 보고, 해당 장면은 담당자 화면에서 직접 처리한다. 다음 처리가 성공하면 자동으로 풀린다. |
| 물품 신고가 승인 대기열에 안 올라옴 | 수량을 못 읽었거나(규칙 모드에서 '여섯 병'처럼 한글 수량) 상한 초과·의약품이다. ⑧ 물품 탭 '검토'에서 사유를 확인하고 직접 승인한다. 규칙 모드에서는 `생수 12병`처럼 숫자로 쓴다. |
