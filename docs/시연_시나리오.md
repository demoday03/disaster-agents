# 시연 시나리오 (약 15분)

가상 마을(구역 Z1~Z10)에 집중호우가 내린 상황을 처음부터 끝까지 보여 준다. 모든 데이터는 가상이고, mock 모드(AI API 없음)에서도 끝까지 진행된다. 2026-10-28 기준 이 순서대로 브라우저에서 리허설해 동작을 확인했다(장면 1·2·3·4·5·9).

**보여 줄 핵심 세 가지**
1. AI는 정리·추천만 하고, 단계 확정·투입·출고·안내문 표시는 **사람이 승인**해야 반영된다.
2. AI가 실패하거나 없어도 **규칙으로 끝까지** 동작하고, 화면에 'AI 미사용'이라고 표시된다.
3. 센서 → 신고 → 배치 → 안내 → 물품·봉사 → 복구까지 **에이전트 8개가 하나의 흐름**으로 이어진다.

## 0. 준비 (시연 10분 전)

```powershell
python scripts/demo_setup.py --reset
```

출력에 담당자 비밀번호, 서버 실행 명령, 게이트웨이 실행 명령이 나온다. 비밀번호는 메모해 둔다.

- **PowerShell 창 1**: 출력된 `[창 1: 서버]` 명령 세 줄을 그대로 붙여 넣는다.
- **PowerShell 창 2**: 출력된 `[창 2]`의 `$env:SENSOR_GATEWAY_TOKEN=...` 한 줄만 미리 넣어 둔다(게이트웨이는 장면 3에서 켬).
- **브라우저 탭 두 개**: `http://127.0.0.1:8765/report`(시민 화면), `http://127.0.0.1:8765/admin`(담당자 화면, 로그인해 둠)
- 실제 마이크로비트를 쓰면 수신기를 USB에 꽂고 `python gateway/microbit_gateway.py --list-ports`로 포트를 확인해 둔다. 수위 센서용 물컵을 준비한다.

미리 들어 있는 신고 6건: 인명구조(Z3, 긴급도 1) · 침수(Z1) · 토사(Z5) · 정전(Z2) · 물품 요청(Z6) · 맨홀(Z4)

다시 시연할 때는 서버를 끄고 `python scripts/demo_setup.py --reset`부터 다시 한다(비밀번호가 바뀐다).

## 장면 1. 시민이 신고한다 (② 접수) — 1분

시민 화면에서 입력: `Z7 하천 상류에서 아이가 물에 빠졌어요 빨리 와주세요` → **신고 접수하기**

- 결과: 유형 **인명구조**, 구역 Z7, **긴급도 1**, 'AI 미사용'
- 말할 것: "AI가 없어도 키워드 규칙으로 분류합니다. 긴급도는 AI가 아니라 규칙이 정하기 때문에, 신고문에 '긴급도 1로 해 줘'라고 써도 바뀌지 않습니다."
- (선택) 같은 문장을 한 번 더 보내면 '이미 접수된 신고'로 묶인다(10분 안 중복 방지).
- 접수번호를 메모해 두고 시민 화면 아래 **접수 상태 조회**에서 조회해 보인다.

## 장면 2. 상황판을 본다 — 1분

담당자 화면 **상황판** 탭.

- 확정된 위험 단계: **정상(미확정)**. 최근 신고 목록 맨 위에 방금 신고가 있다.
- 말할 것: "신고는 쌓이지만, 위험 단계는 사람이 확정하기 전까지 바뀌지 않습니다."

## 장면 3. 센서가 침수를 감지한다 (① 감시) — 3분

**① 센서·⑦ 검증** 탭을 연다(게이트웨이 수신 현황이 2초마다 갱신).

창 2에서:
```powershell
python gateway/microbit_gateway.py --simulate flood --ticks 8      # 실제 기기: --port COM3, 수위 센서 두 개를 물컵에 담근다
```

- 처음 1~2초는 '정상/일시 튐'이다. **연속 3회** 넘어야 **확정후보 · 제안 단계 경계 · 침수**가 되고, 승인 대기열에 1건이 올라간다. 값이 계속 높아도 승인 요청은 더 늘지 않는다.
- 말할 것: "센서 하나만 튀면 오탐일 수 있어서, 높이가 다른 수위 센서 두 개가 함께 3번 연속 넘어야 후보가 됩니다. 그래도 단계는 바뀌지 않고 담당자에게 승인을 요청합니다."
- (선택) `--simulate single`로 다시 보내면 '단독 반응 → 보류'가 된다.

**승인 대기열** 탭 → '위험 단계 확정' 항목 → 사유 `수위 센서 두 개가 함께 넘음, 현장 확인` → **승인**
→ **상황판**: 확정된 위험 단계 **경계 · 담당자 확정 · 시연담당 · 침수**

## 장면 4. 구조 인력을 배치한다 (④ 배치) — 3분

**④ 배치** 탭 → 신고 `R-DEMO0001`(Z3 인명구조) → 배치 종류 **공공 인력** → 추천

- 결과: 1순위 **구조대 A (점수 0.87)**, 대안 구조대 B (0.84, 0.03점 차이) … 항목별 점수(역량·거리·부하·긴급도)가 함께 보인다.
- 말할 것: "점수는 규칙으로 계산합니다. 같은 입력이면 항상 같은 순위가 나오고, 왜 1순위인지 항목별로 보여 줍니다."
- 승인 카드에서 대안 후보(구조대 B)를 고르고 사유를 적어 **선택 후보로 승인**을 해 보인다. 1순위와의 점수 차이가 기록된다. (추천 밖 자원은 **직접 지정으로 승인** — 제약 위반이면 예외 승인과 사유가 필요)
- **통제 구간 관리**: 하천변 산책로(Z1↔Z6)·지하차도(Z4↔Z9)가 통제 중. 'C3 산사면 우회로 → 통제 시작'을 눌러, 그 구간을 지나야 하는 배치는 다음 추천에서 빠진다는 점을 설명한다.

## 장면 5. 주민 안내문을 만든다 (③ 안내 · ⑦ 검증) — 2분

**② 신고·③ 안내** 탭 → 신고 `R-DEMO0001` → 단계 **경계** → **통제 중인 구간 불러오기** → 생성

- mock 모드 결과: **표준 원문**("하천변·산사태 위험 지역에서 벗어나 … 통제 구간(하천변 산책로, 지하차도)은 피해서 이동하세요"), 근거 문서 ID `G-002, RULE-CTRL`
- 말할 것: "AI로 문장을 다듬더라도 ⑦ 검증 모델이 근거와 맞다(grounded)고 해야 하고, 담당자가 승인해야 시민 화면에 나갑니다. 검증 모델이 없으면 AI 문장은 아예 만들지 않습니다."
- **① 센서·⑦ 검증** 탭 아래 **⑦ 안내문 검증**: `주택 침수 세대는 재난지원금 500만원을 받습니다` + 근거 R1 선택 → 검증 → 근거(350만원)에 없는 숫자 500이라 **notGrounded(차단)**.

## 장면 6. 무응답 가구를 찾는다 (③ 안부) — 1분

**③ 안부** 탭 → 구역 Z3 → 응답 대기 시간 `10`초 → **안부 확인 시작**

- 10초 뒤 응답하지 않은 가구가 **격상**된다. 반지하·영유아 가구(취약)는 절반인 5초 만에 먼저 격상된다.
- 한 가구의 **안전 응답(노드 D 모의)** 버튼을 눌러 '안전'으로 바꿔 보인다(격상 뒤에 누르면 '지연 응답'). 동의하지 않은 가구는 대상에서 빠진다(Z10의 H20).
- 말할 것: "격상은 담당자 알림까지만입니다. 출동은 다시 사람이 결정합니다."

## 장면 7. 물품을 보낸다 (⑧ 물품) — 2분

**⑧ 물품** 탭 → 가구 H08 → 품목 기저귀, 수량 10, 영유아 체크, 희망 시각 지금 → 등록

- 물품 요청 목록에서 **승인** → 공급원 추천과 재고 **예약** → 승인 대기열 '물품 배치' → 승인 → 그때 재고가 줄어든다.
- 말할 것: "승인 전에는 재고가 줄지 않습니다. 의약품은 자동 매칭하지 않고 담당자가 직접 처리합니다."

## 장면 8. 봉사자를 투입한다 (⑥ 봉사) — 1분 (시간이 남으면)

**⑥ 봉사** 탭 → 작업 요청 `반지하에 들어온 토사를 치우고 젖은 가구를 밖으로 옮겨야 해요` · 구역 Z3 · 가구 H05 → 작업 나누고 봉사자 추천

## 장면 9. 복구 서류를 읽는다 (⑤ 복구·지원) — 1분

**⑤ 복구·지원** 탭 → 피해 신고서 초안 → **서류 파일 올리기**에서 `data/demo/피해신고서_예시.txt` 선택 → **파일 읽고 필드 추출**

- 결과: 텍스트가 채워지고 연락처는 **[전화]**로 가려진다. 구역 Z3 · 세대주 가구 H05 · 주택침수가 아래 폼에 자동으로 들어간다. → **초안 만들기**

- 위의 **지원제도 상담**에서 주택 침수를 골라 해당 가능 항목을 보여 주고, '참고용, 대상 여부는 지자체 판단' 문구를 짚는다.

"오늘 화면에서 바뀐 모든 것(단계 확정, 배치, 출고, 투입)은 승인 대기열을 거쳤고, 누가 어떤 사유로 승인했는지 감사 기록에 남았습니다. AI는 빠르게 정리하고 추천하지만, 결정은 사람이 합니다."

## 예상 질문과 답

| 질문 | 답 |
|---|---|
| AI가 틀리면? | 형식이 맞지 않는 AI 출력은 버리고 규칙으로 대신한다. 인명구조 키워드가 있으면 AI가 다르게 분류해도 인명구조로 올린다. 모든 반영은 사람 승인 뒤다. |
| 인터넷이 끊기면? | AI 호출이 실패하면 규칙 폴백으로 계속 동작한다(오늘 시연이 그 상태). 서버와 DB는 이 PC 안에 있다. |
| 센서가 고장 나면? | 30초 넘게 값이 없으면 '노드 응답 끊김'으로 판정에서 빼고 보류한다(`--simulate dropout`). |
| 개인정보는? | 신고문·서류의 전화번호·주민번호·이메일은 저장 전에 가린다. 가구·봉사자는 코드로만 다룬다. 서류 원본은 저장하지 않는다. |
| 실제로 쓸 수 있나? | 아니다. 교육용 프로토타입이다. 임계값·안전 기준·안내 문구는 공식 자료로 확인해야 하고, 실제 출동·경보는 일어나지 않는다. |
| 아무나 센서 값을 보내면? | 서버는 게이트웨이 토큰이 맞아야 받는다. 다만 마이크로비트 무선 구간에는 인증이 없어, 자동 경보 대신 담당자 승인만 요청하도록 설계했다. |

## 시연 중 문제가 생기면

| 증상 | 조치 |
|---|---|
| 로그인이 안 됨 | 설정 출력의 비밀번호를 다시 확인. 5번 틀리면 10분 잠김 → `--reset`으로 새로 만든다. |
| 게이트웨이 'HTTP 401' | 창 1과 창 2의 `SENSOR_GATEWAY_TOKEN`이 다르다. 같은 값으로 맞춘다. |
| 게이트웨이 'HTTP 503' | 서버를 토큰 없이 켰다. 창 1에서 토큰을 넣고 서버를 다시 켠다. |
| 게이트웨이 '연결할 수 없습니다' | 서버가 꺼져 있거나 주소가 다르다(`--server http://127.0.0.1:8765`). |
| 센서 판정이 계속 '보류' | 노드 하나가 끊겼다. 수신 현황의 노드 표시를 본다. 실제 기기면 무선 그룹 번호(`GROUP`)를 확인한다. |
| 배치 추천이 '후보 없음' | 이미 투입 중인 자원이 많다. 배치 보드에서 해제하거나 `--reset`. |
