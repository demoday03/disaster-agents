# 마이크로비트 게이트웨이 (① 감시 실시간 입력)

센서 노드 → 수신기 마이크로비트 → PC 게이트웨이 → 서버 → 감시 판정 → 승인 대기열 순서로 이어진다.

```
[노드 A: 수위 2개] ─┐ radio(group 23)
                    ├─▶ [수신기 마이크로비트] ─USB 시리얼─▶ gateway/microbit_gateway.py ─HTTP─▶ webapp/server.py
[노드 B: 기울기·진동]┘                                       (토큰 인증)              /api/sensor/readings
```

| 파일 | 하는 일 |
|---|---|
| `microbit/node_a.py` | P0(낮은 수위)·P1(높은 수위)를 1초마다 읽어 무선 전송 |
| `microbit/node_b.py` | P9(기울기 센서, 기울면 0 · 없으면 내장 가속도계)·P0(진동, 1초 최댓값)을 무선 전송, 기울면 P8 모듈 LED 켬 |
| `microbit/receiver.py` | 무선 메시지를 받아 USB 시리얼로 `S,노드,센서,값` 한 줄씩 출력 |
| `gateway/microbit_gateway.py` | 시리얼을 읽어 1초마다 서버로 묶어 보냄. 기기 없이 시험하는 가상 센서 모드 포함 |
| `webapp/sensors.py` | 서버 쪽 수신·판정. 최근 값만 메모리에 두고, 받을 때마다 감시 규칙으로 다시 판정 |
| (블루투스 모듈) | G 노드 외부 센서 모듈. 노트북과 페어링해 `--bt-port`로 읽는다(아래 1-2) |

## 1. 기기 없이 먼저 시험하기 (가상 센서)

PowerShell 창 두 개를 연다.

```powershell
# 창 1: 토큰을 만들고 서버 실행
python gateway/microbit_gateway.py --new-token        # 출력된 값을 복사
$env:SENSOR_GATEWAY_TOKEN="복사한_토큰"
python webapp/server.py

# 창 2: 같은 토큰으로 게이트웨이 실행
$env:SENSOR_GATEWAY_TOKEN="복사한_토큰"
python gateway/microbit_gateway.py --simulate flood --ticks 10
```

관리자 화면 **센서 탭 → 게이트웨이 수신 현황**에 값이 들어오고, 3초쯤 뒤 '확정 후보'와 승인 요청이 보인다.

| `--simulate` | 보내는 값 | 기대 결과 |
|---|---|---|
| `normal` | 모두 낮음 | 정상 |
| `flood` | 수위 두 개 모두 높음 | 3회 연속 뒤 확정 후보(침수) → 승인 요청 1건 |
| `single` | 낮은 수위만 높음 | 보류(단독 반응, 오탐 가능) |
| `spike` | 한 번만 튐 | 정상(일시 튐 무시) |
| `slope` | 기울기 + 진동 | 확정 후보(사면) |
| `dropout` | 노드 B가 첫 회 뒤 끊김 | 30초 뒤 노드 B 끊김, 보류 |
| `sos` | 센서 정상 + 노드 E의 SOS 버튼 신호(같은 신호 두 번) | 센서 탭 '현장 버튼 신호'에 SOS 한 건(확인 전까지 빨간색) |

## 1-1. 현장 버튼 신호와 내려보내기 (양방향)

```
[노드 C·D·E 버튼] ─E,노드,신호,번호─▶ G ─USB─▶ 게이트웨이 ─▶ 서버 /api/sensor/readings (events)
                  ◀────K,노드,번호──── G ◀─USB─ 게이트웨이            (받았음 → 노드가 재전송을 멈춤)
[모든 노드]       ◀──L0~L3 / X / Q,D── G ◀─USB─ 게이트웨이 ◀─3초마다─ 서버 /api/sensor/downlink
```

- **웹 기능 반영**: 아래 신호는 담당자 화면 버튼과 같은 처리로 기존 기능에 바로 반영한다. 처리자는 `마이크로비트 C`처럼 남는다. 어느 대피소·가구·봉사자인지는 `config/field_nodes.json`(기본 C→S1, D→H01, E→V01)에서 정한다. 지금 상태로 반영할 수 없으면 '반영 안 됨: 사유'로 센서 탭에 남고 담당자가 처리한다.

  | 신호 | 반영 |
  |---|---|
  | C `+1`/`-1` | 출동 탭 대피소 운영 인원 ±1 (수용량 초과·0명 미만이면 반영 안 됨) |
  | D `SAFE` | 안부 탭 해당 가구 응답 (안부 확인이 진행 중일 때만) |
  | E `SOS` | 봉사 탭 SOS 목록에 등록(확인은 봉사 탭에서) |
  | E `IN`/`DONE` | 그 봉사자의 '투입승인' 작업 → 진행, '진행' 작업 → 완료 |
  | 그 밖(C `GOT`, D `SOS`·`NEED`·`DARK`·`LIGHT`, E `HEAT`·`COOL`) | 센서 탭 표시만(급한 것은 담당자 '확인' 전까지 빨간색) |

- **현장 신호(E)**: SOS·체크인·입소/퇴소·안전 응답·정전 등. 서버는 신호를 단계 판정에 쓰지 않고 센서 탭에 보여 준다. SOS·급한 물품·폭염·정전은 담당자가 '확인'을 누를 때까지 열려 있다. 무선 재전송으로 같은 신호가 여러 번 와도 60초 안의 같은 노드·신호·번호는 한 건으로 친다. 신호는 서버 메모리에 최근 200개만 두고, 감사 기록(audit_logs)에 남는다.
- **내려보내기**: 게이트웨이가 3초마다 서버에 **담당자가 확정한** 단계만 묻는다(확정 전 후보는 내려보내지 않음). 바뀌면 `L1`~`L3`(정상은 `X`)를 보내고, 무선 유실에 대비해 30초마다 다시 방송한다. ③ 안부 확인이 시작되면 `Q,D`를 한 번 보낸다(노드 D에 '?'가 뜨고 A를 누르면 `SAFE` 응답).
- 가상 센서 모드에는 수신기가 없어 내려보내기를 하지 않는다.

## 1-2. G 노드 외부 모듈 (블루투스)

```
[외부 센서 모듈 + 블루투스(HC-05/HC-06·ESP32 등)] ─블루투스 시리얼─▶ 노트북(가상 COM 포트) ─▶ 게이트웨이 ─▶ 서버
[노드 A~E] ─radio─▶ [G 마이크로비트] ─USB─▶ 같은 노트북·같은 게이트웨이 ────────────────────────▶ 서버
```

- **왜 노트북이 받나**: G 마이크로비트는 무선(radio)으로 A~E를 받는다. 마이크로비트는 무선과 블루투스를 한 프로그램에서 함께 쓸 수
  없어서(MakeCode에서 블루투스 확장을 넣으면 무선이 빠지고, 마이크로파이썬에는 블루투스가 없음), G가 꽂힌 노트북이 블루투스를 받는다.
  게이트웨이는 두 포트를 함께 읽고, 블루투스 값은 **노드 G**로 서버에 보낸다.
- **연결 순서(Windows)**
  1. 모듈에 전원을 넣고 Windows **설정 → 블루투스 및 장치 → 장치 추가 → 블루투스**에서 모듈(예: `HC-06`)을 고른다. PIN은 보통 `1234` 또는 `0000`.
  2. **설정 → 블루투스 및 장치 → 장치 → 추가 블루투스 설정 → COM 포트** 탭에서 **나가는(Outgoing)** 포트 번호를 확인한다(예: `COM5`).
     `python gateway/microbit_gateway.py --list-ports`에도 '블루투스 시리얼로 보임'으로 나온다.
  3. 실행: `python gateway/microbit_gateway.py --port COM3 --bt-port COM5` (G 마이크로비트와 함께). 블루투스 모듈만 쓸 때는 `--bt-port COM5`만.
     HC-05/06 기본 속도는 9600이다. 다르면 `--bt-baud 115200`.
- **모듈이 보내는 한 줄(줄바꿈으로 끝)**: 아래 중 아무 모양이나 된다.

  | 보내는 줄 | 서버에 들어가는 값 |
  |---|---|
  | `S,G,temp,23.5` | G.temp = 23.5 (마이크로비트와 같은 형식) |
  | `temp=23.5,humidity=61` | G.temp = 23.5, G.humidity = 61 |
  | `T:23.5 H:61` | G.T = 23.5, G.H = 61 |
  | `23.5,61` | `--bt-fields temp,humidity`이면 G.temp·G.humidity, 없으면 G.v1·G.v2 |

  Arduino 예: `Serial.print("temp="); Serial.print(t); Serial.print(",gas="); Serial.println(g);` (블루투스 모듈의 TX/RX에 연결한 시리얼로)
- **담당자 화면**: 센서 탭 **🔵 G 노드 외부 모듈 (블루투스)**에 센서·최근 값·받은 때·수신 중/끊김이 2초마다 보인다.
  temp·humidity·gas·co2·dust·pm25·light·distance 같은 이름은 '온도 ℃'처럼 한글 이름과 단위로 보여 준다. 노드 목록에도 `G 연결`이 뜬다.
- **판정에는 쓰지 않음**: 외부 모듈 값은 임계값이 없어 위기 단계 판정·승인 요청에 쓰지 않고 표시만 한다. 판정에 넣으려면
  `config/monitor.json`의 `nodes`·`sensors`에 `G`와 임계값을 더해야 한다(설치 점검으로 값을 정한 뒤).
- **기기 없이 시험**: `python gateway/microbit_gateway.py --simulate normal --bt-simulate` (가상 온도·습도·가스).
- 블루투스 연결이 끊겨도 게이트웨이는 멈추지 않고 3초마다 다시 연결한다. 30초 넘게 값이 없으면 화면에 '끊김'.

## 2. 실제 마이크로비트 연결

1. https://python.microbit.org 에서 `microbit/` 파일 세 개를 각각 마이크로비트에 올린다(노드 A, 노드 B, 수신기). 세 파일의 `GROUP` 번호는 같아야 하고, 같은 교실의 다른 팀과는 달라야 한다.
2. 수신기 마이크로비트를 PC에 USB로 꽂는다(충전 전용 케이블이 아니라 데이터 케이블).
3. `pip install pyserial` (실제 기기를 읽을 때만 필요)
4. `python gateway/microbit_gateway.py --list-ports`로 포트를 확인한다(Windows는 `COM3` 같은 이름).
5. 서버를 토큰과 함께 켠 상태에서 `python gateway/microbit_gateway.py --port COM3`

배선(2026-11-01 설치 점검으로 확정, Keyestudio 센서 쉴드): 수위 센서 두 개는 노드 A의 P0·P1 아날로그(마름 0~112, 젖음 약 300 → 임계값 200). 노드 B는 진동 센서 AO → P0(가만히 0~36, 흔들면 수백), 기울기 센서(매직 라이트 컵) S → P9 · L → P8. 이 기울기 센서는 세워 두면 1, 기울거나 돌리면 0이고 모듈에 풀업이 있어 마이크로비트 쪽 풀업은 끈다. 기울기 센서가 없으면 `node_b.py`의 `USE_ACCEL = True`로 내장 가속도계를 쓴다.

강우 단계는 게이트웨이에서 `--rain-stage 3`처럼 넘긴다(3 이상이면 침수 확정 후보가 '위험'으로 올라감). 생략하면 서버가 가진 값(처음 0)을 유지한다.

## 3. 안전 장치

- **사람 확정**: 게이트웨이 값은 단계를 바꾸지 않는다. 확정 후보는 승인 대기열에 올라가고, 담당자가 승인해야 상황판 단계가 바뀐다.
- **중복 요청 방지**: 같은 단계·같은 위험 유형이 이미 대기 중이거나 확정돼 있으면 새로 올리지 않는다. 다른 위험(예: 침수 다음 사면)은 새로 올린다.
- **인증**: 서버와 게이트웨이가 같은 `SENSOR_GATEWAY_TOKEN`(16자 이상)을 써야 한다. 토큰이 없으면 서버의 수신·내려보내기 경로가 닫혀 있다(503). 로그인 쿠키로는 이 경로를 쓸 수 없다. 반대로 현장 신호 '확인'은 담당자 로그인(CSRF 포함)으로만 된다.
- **시각**: 마이크로비트에는 시계가 없어 게이트웨이가 받은 시각을 붙이고, 서버는 자기 시계와 5초 넘게 어긋나는 값을 버린다.
- **오래된 값·끊김**: 30초(`stale_sec`) 넘게 값이 없는 센서·노드는 판정에서 빼고 '보류'로 둔다.
- **USB 끊김**: 노트북 절전이나 케이블 흔들림으로 시리얼이 끊겨도 게이트웨이는 멈추지 않고 3초마다 다시 연결한다. 끊긴 동안 30초가 넘으면 서버 판정은 '보류(노드 끊김)'가 된다. 시연 중에는 노트북 절전을 끈다.
- **저장하지 않음**: 측정값은 서버 메모리에만 두고(최대 5000개), 판정 결과와 승인 요청만 DB에 남는다.

## 4. 한계 (발표·보고서에 적을 것)

- 마이크로비트 무선(radio)에는 암호화·인증이 없다. 같은 그룹 번호의 다른 마이크로비트가 가짜 값을 보낼 수 있다. 그래서 자동 경보를 내지 않고 담당자 승인만 요청한다.
- 임계값(`config/monitor.json`)은 임시값(`calibrated: false`)이다. 설치 점검에서 물 높이별 실제 값을 재서 바꿔야 한다.
- 수위 센서를 물에 계속 담가 두면 전극이 부식된다. 시연에서는 컵에 담갔다 빼는 식으로 쓴다.
- 서버를 다시 켜면 메모리 버퍼가 비어 처음 30초는 판정이 '보류'일 수 있다.
