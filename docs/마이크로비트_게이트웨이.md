# 마이크로비트 게이트웨이 (① 감시 실시간 입력)

센서 노드 → 수신기 마이크로비트 → PC 게이트웨이 → 서버 → 감시 판정 → 승인 대기열 순서로 이어진다.

```
[노드 A: 수위 2개] ─┐ radio(group 23)
                    ├─▶ [수신기 마이크로비트] ─USB 시리얼─▶ gateway/microbit_gateway.py ─HTTP─▶ webapp/server.py
[노드 B: 기울기·진동]┘                                       (토큰 인증)              /api/sensor/readings
```

| 파일 | 하는 일 |
|---|---|
| `microbit/node_a.py` | P0(낮은 수위)·P1(높은 수위)를 1초마다 읽어 무선 전송 |
| `microbit/node_b.py` | P8(기울기 스위치, 없으면 내장 가속도계)·P1(진동, 1초 최댓값)을 무선 전송 |
| `microbit/receiver.py` | 무선 메시지를 받아 USB 시리얼로 `S,노드,센서,값` 한 줄씩 출력 |
| `gateway/microbit_gateway.py` | 시리얼을 읽어 1초마다 서버로 묶어 보냄. 기기 없이 시험하는 가상 센서 모드 포함 |
| `webapp/sensors.py` | 서버 쪽 수신·판정. 최근 값만 메모리에 두고, 받을 때마다 감시 규칙으로 다시 판정 |

## 1. 기기 없이 먼저 시험하기 (가상 센서)

PowerShell 창 두 개를 연다.

```powershell
# 창 1: 토큰을 만들고 서버 실행
python gateway/microbit_gateway.py --new-token        # 출력된 값을 복사
$env:SENSOR_GATEWAY_TOKEN="복사한_토큰"
python webapp/server.py

# 창 2: 같은 토큰으로 게이트웨이 실행
$env:SENSOR_GATEWAY_TOKEN="복사한_토큰"
python gateway/microbit_gateway.py --simulate flood --ticks 10
```

관리자 화면 **센서 탭 → 게이트웨이 수신 현황**에 값이 들어오고, 3초쯤 뒤 '확정 후보'와 승인 요청이 보인다.

| `--simulate` | 보내는 값 | 기대 결과 |
|---|---|---|
| `normal` | 모두 낮음 | 정상 |
| `flood` | 수위 두 개 모두 높음 | 3회 연속 뒤 확정 후보(침수) → 승인 요청 1건 |
| `single` | 낮은 수위만 높음 | 보류(단독 반응, 오탐 가능) |
| `spike` | 한 번만 튐 | 정상(일시 튐 무시) |
| `slope` | 기울기 + 진동 | 확정 후보(사면) |
| `dropout` | 노드 B가 첫 회 뒤 끊김 | 30초 뒤 노드 B 끊김, 보류 |

## 2. 실제 마이크로비트 연결

1. https://python.microbit.org 에서 `microbit/` 파일 세 개를 각각 마이크로비트에 올린다(노드 A, 노드 B, 수신기). 세 파일의 `GROUP` 번호는 같아야 하고, 같은 교실의 다른 팀과는 달라야 한다.
2. 수신기 마이크로비트를 PC에 USB로 꽂는다(충전 전용 케이블이 아니라 데이터 케이블).
3. `pip install pyserial` (실제 기기를 읽을 때만 필요)
4. `python gateway/microbit_gateway.py --list-ports`로 포트를 확인한다(Windows는 `COM3` 같은 이름).
5. 서버를 토큰과 함께 켠 상태에서 `python gateway/microbit_gateway.py --port COM3`

배선은 가정이다(설치 점검에서 확정): 수위 센서 두 개는 P0·P1 아날로그, 진동(압전)은 노드 B의 P1, 기울기 스위치는 P8. 기울기 스위치가 없으면 `node_b.py`의 `USE_ACCEL = True`로 내장 가속도계를 쓴다.

강우 단계는 게이트웨이에서 `--rain-stage 3`처럼 넘긴다(3 이상이면 침수 확정 후보가 '위험'으로 올라감). 생략하면 서버가 가진 값(처음 0)을 유지한다.

## 3. 안전 장치

- **사람 확정**: 게이트웨이 값은 단계를 바꾸지 않는다. 확정 후보는 승인 대기열에 올라가고, 담당자가 승인해야 상황판 단계가 바뀐다.
- **중복 요청 방지**: 같은 단계·같은 위험 유형이 이미 대기 중이거나 확정돼 있으면 새로 올리지 않는다. 다른 위험(예: 침수 다음 사면)은 새로 올린다.
- **인증**: 서버와 게이트웨이가 같은 `SENSOR_GATEWAY_TOKEN`(16자 이상)을 써야 한다. 토큰이 없으면 서버의 수신 경로가 닫혀 있다(503). 로그인 쿠키로는 이 경로를 쓸 수 없다.
- **시각**: 마이크로비트에는 시계가 없어 게이트웨이가 받은 시각을 붙이고, 서버는 자기 시계와 5초 넘게 어긋나는 값을 버린다.
- **오래된 값·끊김**: 30초(`stale_sec`) 넘게 값이 없는 센서·노드는 판정에서 빼고 '보류'로 둔다.
- **저장하지 않음**: 측정값은 서버 메모리에만 두고(최대 5000개), 판정 결과와 승인 요청만 DB에 남는다.

## 4. 한계 (발표·보고서에 적을 것)

- 마이크로비트 무선(radio)에는 암호화·인증이 없다. 같은 그룹 번호의 다른 마이크로비트가 가짜 값을 보낼 수 있다. 그래서 자동 경보를 내지 않고 담당자 승인만 요청한다.
- 임계값(`config/monitor.json`)은 임시값(`calibrated: false`)이다. 설치 점검에서 물 높이별 실제 값을 재서 바꿔야 한다.
- 수위 센서를 물에 계속 담가 두면 전극이 부식된다. 시연에서는 컵에 담갔다 빼는 식으로 쓴다.
- 서버를 다시 켜면 메모리 버퍼가 비어 처음 30초는 판정이 '보류'일 수 있다.
