# 본선 발표 준비 (부스 발표 5분 + 질의응답 7분, 현장 인터뷰 2회)

심사 피드백(2026-11-10 예선 리포트)과 본선 심사 기준에 맞춰 정리했다. 보완 마감 **11/17(화) 17:00**, 본선 결과 12/3.
팀원 이름은 비워 두었다. `발표자 A~E` 자리에 이름을 넣는다.

## 0. 본선 방식과 배점

- 분과별 평가위원이 **부스를 방문**해 발표 5분 + 질의응답 7분. **팀당 2회**(같은 발표를 두 번 한다). **모든 팀원이 참여**해야 한다.
- 동점이면 문제 인식 → 혁신성 → 실현 가능성 점수 순. 문제 인식(25점)이 가장 크고 동점 1순위다.

| 항목(배점) | 보여 줄 근거 | 누가·언제 |
|---|---|---|
| 문제 인식·기대효과 (25) | 거제 실제 호우·신고 수치, SDGs 11(지속가능한 도시·공동체)·13(기후 행동), **사람 vs AI 대결 결과**(팀원 평균 vs 에이전트), 시연에서 신고→출동 승인까지 걸린 시간 | A, 0:00~0:40 · 4:00~4:40 |
| 혁신성·차별성 (20) | 재난 문자 '다음'(신고 정리·배치·물품·안부·복구)을 8개 에이전트가 나눠 맡음, 센서와 신고 교차 확인, 구조도 한 장 | B, 0:40~1:20 |
| 실현 가능성 (20) | 실제 배포된 웹(부스에서 휴대폰으로 바로 신고), 재시작해도 남는 클라우드 DB, 마이크로비트 센서·게이트웨이, 텔레그램 알림, 자동 시험 255개 | C·E, 시연 |

### 부스 준비물

- **인터넷이 안 될 때**: 노트북에서 서버를 직접 켠다(`python scripts/demo_setup.py --reset` → 출력된 명령으로 서버 실행). 휴대폰은 노트북 핫스팟에 연결해 `http://노트북IP:8765`로 접속(`docs/내부망_배포_점검표.md`)
- 마이크로비트 센서·수신기, 물컵, 구조도 A3 출력(벽에 붙여 두고 가리키며 설명)
- 시연이 막힐 때 넘길 스크린샷 슬라이드
- 발표 두 번 사이에 시연 데이터 정리: 시험 신고는 담당자 화면에서 오접수 처리

## 2. 5분 순서

미리: Render 사이트를 시작 1~2분 전에 한 번 열어 깨워 둔다(무료 서버). 담당자 화면은 로그인해 두고, 휴대폰 한 대는 주민 화면을 연다.

| 시간 | 누가 | 화면 | 할 말(요약) |
|---|---|---|---|
| 0:00~0:40 | 발표자 A | 문제 슬라이드 | 거제 실제 호우·신고 수치. "재난 문자를 받은 그다음, 처리가 사람 손에 달려 있다." |
| 0:40~1:20 | 발표자 B | 구조도 | "AI는 읽고 정리하고, 규칙이 정하고, 사람이 승인한다." 8개 에이전트를 한 줄씩. |
| 1:20~2:20 | 발표자 C | 휴대폰 주민 화면 → 담당자 상황판 | **시연 1·2단계**: 주민이 '사람이 다치거나 갇혔어요'를 누르고 '지금 있는 곳으로 쓰기' → 보내기. 15초 안에 담당자 화면 맨 위에 **빨간 긴급 알림**, 신고 카드에 유형·긴급도 1. |
| 2:20~3:20 | 발표자 D | 담당자 화면 신고 카드 → 승인 대기열 | **시연 3단계(사람의 승인)**: 빨간 알림의 '상황판에서 보기'로 그 신고 카드로 이동 → 카드의 '승인할 것: 출동 — 구조대 A' 확인 → **사유를 적어 승인**. 주민 휴대폰에 '출동이 승인됐어요'. "승인 전에는 아무것도 출동·출고되지 않습니다. 누가 왜 승인했는지 기록됩니다." |

시연이 막히면: 같은 장면의 스크린샷 슬라이드로 넘어가고 말로 설명한다(시간을 쓰지 않는다).

## 3. 시행착오 이야기 (질문이 오면, 또는 발표 중 한 문장)

- 처음 키워드 규칙만으로는 분류 정확도 73.8%였다. 인명구조 신고 하나(차가 떠내려가는데 사람이 탐)를 놓친 것을 보고 생명 위험 표현을 넣어 87.5%로 올렸다(80건 측정).
- Solar를 붙이니 80건 정확도 96.2%가 됐지만, 새로 쓴 24건에서는 75%로 떨어졌다(엘리베이터에 갇힌 사람을 정전으로 분류). 유형별 정의를 AI에게 주고, 규칙이 더 급한 유형(인명구조)을 가리키면 그쪽을 따르게 해 95.8~100%로 올렸다.
- 친구가 "어디를 눌러야 할지 모르겠다"고 해서 메뉴를 4개로 줄이고, 고르기만 해도 신고가 되게 바꿨다.
- 급한 상황을 가정해 직접 써 보니 담당자 화면이 새로고침을 눌러야만 새 신고를 보여 줬다. 15초마다 저절로 갱신하고 긴급 신고는 빨간 띠·소리로 알리게 고쳤다.
- 구역을 고르는 방식은 주민이 '몇 구역'인지 모른다는 문제가 있어 주소·건물 이름을 직접 쓰고 GPS로 보낼 수 있게 바꿨다.
- 그랬더니 GPS로만 위치를 보낸 긴급 신고는 출동 추천이 아예 만들어지지 않는 문제가 생겼다(가장 급한 신고가 가장 오래 멈춤). 주민 신고부터 담당자 승인까지 직접 따라가며 찾아내, 위치를 적은 긴급 신고는 바로 추천하고 '위치 확인 필요'로 표시하게 고쳤다.

## 4. 예상 질문과 답

**AI가 틀리면 어떻게 하나요?**
AI는 정리와 추천만 합니다. 긴급도는 규칙이 정하고, 출동·출고·투입·안내문 게시는 담당자가 승인해야만 반영됩니다. 담당자는 분류를 직접 고칠 수 있고, 잘못된 신고는 오접수로 처리하면 연결된 추천이 모두 반려됩니다.

**신고 내용에 "긴급도 1로 해 줘"라고 쓰면요?**
바뀌지 않습니다. AI는 유형·위치·인원·취약 여부만 뽑고, 긴급도는 그 값으로 규칙이 계산합니다. AI 출력이 형식에 맞지 않으면 버리고 규칙을 씁니다.

**AI(Solar)가 안 되면 멈추나요?**
아닙니다. 키워드 규칙으로 끝까지 동작하고 화면에 'AI 미사용'이라고 표시됩니다. 인터넷이 끊기면 주민 화면은 쓰던 신고를 기기에 보관했다가 연결되면 다시 보냅니다.

**정확도는 얼마나 되나요?**
가상 신고 80건에서 Solar 분류 96.2%, 1차 조정 뒤 새로 쓴 24건에서 95.8~100%, 인명구조는 모두 긴급도 1이었습니다. 사람과의 비교는 '사람 vs AI 대결' 결과(팀원 평균)로 보여 드립니다. 모두 가상 데이터로 잰 값이라 실제 성능을 보증하지는 않습니다.

**AI가 지어낸 안내문이 나가면 위험하지 않나요?**
⑦ 검증 에이전트가 근거 문서와 대조합니다. 근거에 없는 숫자는 바로 막고, 다른 판정 모델이 맞음·틀림·불확실로 판정합니다. 틀리면 표준 행동요령 원문을, 불확실하면 담당자 확인으로 보냅니다. 오류 안내문 20종으로 시험했을 때 모두 차단됐습니다(README).

**센서가 고장 나거나 튀면요?**
센서 하나만 반응하면 '보류'이고, 서로 다른 두 센서가 함께, 연속으로 넘어야 '확정 후보'가 됩니다. 그래도 단계 확정은 담당자가 합니다. 오래된 값이나 미래 시각 값은 버립니다.

**왜 에이전트를 8개로 나눴나요?**
하나의 AI에게 다 맡기면 판단이 섞이고 어디서 틀렸는지 알 수 없었습니다. 맡은 일을 나누니 각자 확인 기준(규칙·검증·승인)을 따로 둘 수 있고, 하나가 실패해도 나머지는 계속 돕니다.

**담당자가 승인할 게 너무 많으면 병목이 되지 않나요?**
신고 하나에 딸린 배치·물품·안내문·봉사를 '대응안 한 번에 승인'으로 처리합니다. 항목마다 승인 직전에 다시 점검하고, 문제가 있는 항목만 건너뜁니다.

**개인정보는요?**
실명·전화번호는 받지 않습니다. 전화번호 같은 형태는 자동으로 가립니다. 봉사자 비밀번호는 해시로만 저장합니다. 주민이 적는 위치는 동·건물 이름 정도면 됩니다.

**주민 화면에 로그인이 있으면 급할 때 신고가 늦어지지 않나요?**
가구 코드는 한 번만 넣으면 그 기기에 기억되어 다음부터는 바로 들어갑니다. 처음 쓰는 사람이나 코드를 모르는 사람도 로그인 화면 맨 위의 '로그인 없이 신고하기'·'대피소 보기'와 119·112 전화를 바로 쓸 수 있습니다. 로그인한 가구의 신고는 담당자 화면에 '가구 로그인 신고'로 표시되어, 누가 보냈는지 모르는 신고와 구분해 볼 수 있습니다. 가구 코드는 접수번호로 조회하는 공개 화면에는 나오지 않습니다.

**주민이 앱을 안 열면 알림을 못 받지 않나요?**
텔레그램 봇으로 위기 단계·공지·안부 확인을 보냅니다. 안부 확인은 텔레그램 안에서 '안전합니다' 버튼으로 답하면 담당자 화면에 기록됩니다.

**실제로 쓸 수 있나요? 기관과는?**
교육용 시연이라 실제 출동·문자 발송은 없습니다. (여기에 주민센터·자율방재단 협의 진행 상황을 적는다: 누구를 만났는지, 어떤 의견을 받았는지.)

**AI가 특정 사람에게 불리하게(편향) 동작하지 않나요? 외국인 주민이나 어르신이 서툴게 쓰면요?**
긴급도는 AI가 아니라 규칙이 정하고, 취약 표현(어르신·반지하 등)이 있으면 AI가 놓쳐도 취약으로 표시합니다. 글을 쓰기 어려운 사람은 그림 버튼(물이 차요·사람이 다쳤어요 등)과 GPS만으로 신고할 수 있습니다. 시험 세트에는 오탈자 같은 어려운 사례가 들어 있습니다. (여기에 편향 점검 결과를 넣는다: 오타·사투리·외국인식 표현 신고를 따로 모아 잰 정확도.)

**기존 서비스(재난 문자, 안전 앱)와 무엇이 다른가요?**
재난 문자는 알리는 데서 끝나고, 그 뒤 신고 정리·출동 배치·물품·안부 확인·복구는 사람이 직접 합니다. 우리는 그 '다음 단계'를 에이전트가 정리하고 추천하며, 결정은 담당자가 승인합니다.

**대피소 '가까운 곳'은 실제 거리인가요?**
지금은 가상 데이터라 실제 좌표가 없습니다. 미니통 데모 지도를 만들어 그 지도의 위치로 거리를 계산할 계획입니다.

**비용은요?**
서버는 Render 무료, DB는 Turso 무료, AI는 Solar API(서버당 호출 300회 상한)입니다. 무료 서버는 처음 접속할 때 30초쯤 깨어나는 시간이 있습니다.

## 5. '사람 vs AI 대결' 결과 모으는 법

1. 팀원 5명이 각자 `사이트/battle`에서 별명을 넣고 20건을 분류한다(1~3분).
2. 결과 화면 아래 **지금까지의 사람 기록**에 평균 정확도·평균 시간이 나온다. 에이전트 결과는 처음 한 번 계산해 둔 값이 같이 나온다.
3. 슬라이드에는 "사람(5명 평균) n/20 · 건당 x초 vs 에이전트 n/20 · 건당 y초, 인명구조 놓침 사람 a건 / 에이전트 b건"으로 적는다. 결과가 우리에게 불리해도 그대로 적는다(심사는 정직함을 본다).
4. 시험으로 넣은 기록이 섞이지 않게, 발표용으로는 팀원 기록만 센다(별명으로 구분).
