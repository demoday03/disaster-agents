# 학교 내부망 배포 점검표 (배포 ② 단계)

배포 순서는 ① 실행 PC(localhost) → ② 학교 내부망 → ③ HTTPS 서버다(`docs/제안서_수정안_배포구조.md`). 이 문서는 ②로 넘어갈 때 확인할 것과 실행 방법을 정리한다. 2026-10-28 보안 점검 결과를 반영했다.

## 1. 서버가 스스로 막는 것 (코드로 강제)

`python webapp/server.py`는 아래 조건이 맞지 않으면 **켜지지 않는다**(`check_bind_policy`).

| 조건 | 이유 |
|---|---|
| `WEBAPP_HOST`가 localhost가 아니면 `WEBAPP_ALLOW_LAN=1`이 있어야 함 | 실수로 네트워크에 여는 것을 막는다 |
| `0.0.0.0`(모든 네트워크)은 거부, 이 PC의 내부망 IP를 지정 | 와이파이·유선·VPN 모두에 열리는 것을 막는다 |
| HTTPS 인증서(`WEBAPP_TLS_CERT`·`WEBAPP_TLS_KEY`)가 있어야 함. 시연 때만 `WEBAPP_ALLOW_HTTP_LAN=1`로 예외 | HTTP면 같은 네트워크에서 로그인 쿠키·비밀번호가 보인다 |
| `WEBAPP_ALLOWED_HOSTS`에 접속 주소가 있어야 함 | Host 허용 목록(아래) |
| 담당자 계정이 하나 이상 있어야 함 | 관리자 화면을 아무도 못 쓰는 상태로 열지 않는다 |

## 2. 이번에 추가한 보안 장치

| 장치 | 내용 | 확인한 시험 |
|---|---|---|
| Host 허용 목록 | 허용하지 않은 주소(Host 헤더)로 온 요청은 421로 거절. 악성 사이트가 DNS를 바꿔 이 서버에 요청을 보내는 공격(DNS 리바인딩)을 막는다 | `TestNetworkSecurity.test_unknown_host_rejected` |
| 공개 신고 횟수 제한 | 접속 IP당 분당 10건(`WEBAPP_INCIDENT_PER_MIN`). 신고 폭주와 AI 호출 한도 소진을 막는다 | `test_incident_rate_limit_per_ip` |
| 로그인 IP 제한 | 계정별 5회 잠금에 더해 IP당 10분 30회 | — |
| 요청 시간 제한 | 30초 안에 요청을 다 보내지 않으면 연결을 끊는다(느린 요청으로 서버 붙잡기 방지). HTTPS 핸드셰이크도 요청 스레드에서 처리 | 연결만 하고 가만히 있는 클라이언트가 있어도 다른 요청이 0.01초에 처리됨(수동 확인) |
| 보안 헤더 | 다른 사이트 안에 끼워 넣기 금지(`X-Frame-Options`, `frame-ancestors`), 주소 유출 방지(`Referrer-Policy`) | `test_security_headers` |
| HTTPS | 인증서를 지정하면 서버가 직접 TLS 1.2 이상으로 동작하고 쿠키에 `Secure`가 붙는다 | 자체 서명 인증서로 수동 확인 |
| AI 호출 한도 | 서버 전체 1000회(`SOLAR_MAX_CALLS`). 넘으면 규칙 폴백. `/api/health`의 `llm_calls`로 확인 | — |
| 센서 게이트웨이 토큰 | 게이트웨이 경로는 16자 이상 토큰이 맞아야 받는다. 토큰이 없으면 경로가 닫힘 | `TestSensorGateway`, `TestSensorGatewayDisabled` |
| 서류 업로드 | 담당자 로그인·CSRF 확인 뒤에만 큰 본문(최대 7MB)을 읽는다. 원본 파일은 저장하지 않고, 외부 API 전송 전 동의 확인 | `test_recovery_parse_text_file_and_limits`, `test_document_parse_then_extract_fields` |

이미 있던 장치: 비밀번호 PBKDF2 해시, 세션 토큰 해시 저장, CSRF 토큰, SameSite=Strict 쿠키, 다른 사이트에서 온 POST 거절, 담당자 권한 검사, 승인 처리자를 로그인 계정으로 기록, 500 오류 원인은 콘솔에만.

## 3. 실행 방법

### 3-1. 인증서 만들기 (한 번)

학교 전산 담당에게 내부 인증서를 받을 수 있으면 그것을 쓴다. 없으면 자체 서명 인증서를 만든다(Git for Windows에 openssl이 들어 있다).

```bash
openssl req -x509 -newkey rsa:2048 -nodes -days 180 -keyout data/key.pem -out data/cert.pem \
  -subj "/CN=192.168.0.10" -addext "subjectAltName=IP:192.168.0.10"
```

`192.168.0.10`은 서버 PC의 내부망 IP로 바꾼다(`ipconfig`로 확인). 자체 서명 인증서는 접속하는 PC의 브라우저에 '안전하지 않음' 경고가 뜬다. 담당자 PC에 `cert.pem`을 신뢰할 수 있는 인증서로 등록하면 경고가 사라진다. `key.pem`은 다른 사람과 공유하지 않는다(`.gitignore`에 `*.pem` 추가됨).

### 3-2. 서버 실행

```powershell
$env:WEBAPP_HOST="192.168.0.10"
$env:WEBAPP_ALLOW_LAN="1"
$env:WEBAPP_ALLOWED_HOSTS="192.168.0.10:8765"
$env:WEBAPP_TLS_CERT="data\cert.pem"
$env:WEBAPP_TLS_KEY="data\key.pem"
python webapp/server.py
```

접속: `https://192.168.0.10:8765/report`(시민), `https://192.168.0.10:8765/admin`(담당자)

시연 중 잠깐만 HTTP로 열 때(권장하지 않음): 인증서 두 줄 대신 `$env:WEBAPP_ALLOW_HTTP_LAN="1"`. 서버가 경고를 출력한다.

## 4. 열기 전에 사람이 확인할 것

- [ ] 학교 전산 담당(정보부장)에게 내부망에서 서버를 여는 것을 허락받았다
- [ ] Windows 방화벽에서 8765 포트를 **개인/도메인 네트워크에만** 열었다(공용 네트워크 X)
- [ ] 담당자 계정 비밀번호는 12자 이상이고 사람마다 따로 만들었다(`scripts/create_user.py`). 공용 계정을 돌려 쓰지 않는다
- [ ] 시연용 계정(`시연담당`)과 시연 DB(`data/demo.db`)를 운영에 쓰지 않는다
- [ ] 실제 개인정보(이름·주소·연락처)를 넣지 않는다. 가구·봉사자는 코드(H01, V01)로만 다룬다
- [ ] `data/disaster.db`를 정기적으로 복사해 둔다(서버를 끈 상태에서 `.db` 파일 복사). 복사본도 같은 수준으로 보관한다
- [ ] `UPSTAGE_API_KEY`는 서버 PC 환경변수에만 있다. 코드·채팅·USB에 남기지 않았다
- [ ] 화면 위쪽의 '교육용 시연 시스템' 경고가 보인다. 실제 재난 신고는 119·112로 해야 한다는 점을 참가자에게 알렸다

## 5. 아직 남은 위험 (③ HTTPS 서버로 가기 전에 해결)

| 위험 | 현재 상태 | 다음 단계 |
|---|---|---|
| 공개 신고·접수번호 조회는 로그인 없이 가능 | 의도된 설계(시민용). IP당 횟수 제한만 있음. 접수번호는 32비트 무작위라 추측은 어렵지만, 조회 결과에 마스킹된 신고 내용이 보인다 | 조회 횟수 제한, 조회 시 신고자 확인(간단한 비밀번호) 추가 |
| 같은 학교 공유기 뒤의 여러 사람이 같은 IP로 보일 수 있음 | 교실 전체가 분당 10건 제한을 함께 쓸 수 있다 | 시연 규모에 맞게 `WEBAPP_INCIDENT_PER_MIN` 조정 |
| 감사 기록(audit_logs)을 화면에서 볼 수 없음 | DB에는 남는다 | 관리자 전용 감사 기록 화면 |
| 계정 관리(비밀번호 변경·비활성화) 화면 없음 | 스크립트로만 생성 | 관리자 화면에 추가 |
| 표준 라이브러리 HTTP 서버 | 학교 내부망 시연 규모(수십 명)용. 운영용으로 설계된 서버가 아니다 | ③ 단계에서는 nginx 같은 리버스 프록시 뒤에 둔다 |
| 마이크로비트 무선 구간 | 암호화·인증 없음 | 담당자 승인으로만 반영(현재 설계 유지) |
